# T129 first-draw hitch fix (patch 0577) on the door walk, 11 Nov 2026

> **Found:** Patch 0577 (EDEN_UP_PREP_UNREAD_HANDLE) removed every refused pipeline build on the door walk: 0 refused against 6-7, and pipeline time on the GPU thread fell from about 400 ms to about 145 ms.
>
> **So:** The first-draw hitch fix works on this route and its check mode passed on a small sample; it needs more routes before it goes into the play settings.

Batch: `eglantine-logs-2026-11-05/auto-20261111-201720-batch-t129-prep-door` (build T129 = T128 + heap
steal + 0577 + 0578, 01.219.028). Six runs, in this order: c1 control, u2 count only, u1 fix on,
v1 fix on + check, c2 control, u1b fix on. Read from the raw logs (`eden_log.txt`, 5 s fps lines,
`result.json`, frames); `card.md` only for flash counts and the standing phases.

Words, one line each:
- **pipeline**: the compiled drawing recipe the GPU needs before it can draw one kind of object.
- **kept translation**: shader prep's copy on disk of a finished shader translation, reused instead of translating again.
- **refused**: shader prep decides it cannot reuse the kept copy and translates again on the GPU thread while playing (the hitch).
- **rescued**: a pipeline the fix lets through that the old code refused.
- **unread handle**: a texture slot whose number the kept translation never looked at; the old code refused for it, the fix skips it.
- **depth (kind)**: a shadow-style texture read (compares against depth); it never reads its handle.
- **worst frame**: the slowest single frame in a 5 s window (the app's own "5 s" fps line).

## Short answer

1. **The fix removes every refused build on this route.** Controls refused 6 (c1) and 7 (c2)
   pipelines, all "texture handle", each translated on the GPU thread in 24-71 ms. With the fix on
   (u1, u1b): 0 refused, 6 of 6 rescued in each run, and **no pipeline build of 10 ms or more
   anywhere** in the run. Pipeline time on the GPU thread fell from 368 / 444 ms (c1 / c2) to
   146 / 145 ms.
2. **The check passes, on a small sample.** v1: 4 rescued, "4 the same, 0 differ, 0 fresh read a
   skipped word". Every skipped slot in every run is of the "depth" kind, which matches the reason
   the fix was built on. Not covered: the 2 keys drawn at about 103 s (v1 did not draw them), the
   2 extra door keys c2 drew, and the fault-injection run (`_VERIFY=2`) that proves the comparison
   can see a difference.
3. **Visible gain at the door, none visible at the first house draw.** Worst frame in the door
   window: 154 and 155 ms with the fix, 190-226 ms in the four runs that built those pipelines
   (c1, u2, v1, c2). The first house draw sits inside the load's own 650-740 ms frame in every
   run, so its 32 ms build cannot be seen there. Standing fps unchanged (22.1-22.4 in all six).
4. **No picture fault seen** in the frames after the door (u1, v1, u1b against c1), and the flash
   count is no different from the controls.
5. **Ready for a test build: almost.** One more run first: the full play route with
   `EDEN_UP_PREP_UNREAD_HANDLE=1` + `_VERIFY=1`, plus one short `_VERIFY=2` run. If that shows
   0 differ and 0 fresh read, turn it on by default in the next test build.

## Verdict

- **Removes the refused builds**: yes, all of them on this route (6 of 6 in u1 and u1b, 0 builds of
  10 ms or more, GPU-thread pipeline time down by about 220-300 ms a run).
- **Proven equal by the check**: yes for the 4 pipelines v1 drew (4 the same, 0 differ, 0 fresh
  read). It is not yet shown for the other keys, or for the check's own fault detection.
- **Visible gain in the worst frames**: yes at the door (154-155 ms against 190-226 ms). Not visible
  at the first house draw, which the load stall hides.
- **On by default in a test build**: after one more cheap step. Run a play route with
  `EDEN_UP_PREP_UNREAD_HANDLE=1` + `EDEN_UP_PREP_UNREAD_HANDLE_VERIFY=1`, which covers many more
  keys, other kinds than depth too if they show up, and the 103 s pair. Add one short door run with
  `_VERIFY=2`, which must show exactly 1 differ. If both pass, turn it on by default. It costs
  nothing when off (same reasons and timings in c1/c2 as before), and when it goes wrong the
  failure shows up in the log.
